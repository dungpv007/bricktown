# BrickTown — Maze Mode (Plan)

Builds on Phase 1 + the figures/colours batch. Phase 1 Global Constraints still bind (pure-TS core with tests, kid-first touch UI ≥64px, i18n vi+en, Playwright e2e, shared caches never disposed by consumers).

## User decisions (2026-10-01)

- New main-menu mode "Mê cung" (🌀): build a maze, with ready-made maze templates.
- After building, the kid can pick a vehicle and **drive out of the maze**.
- Every maze REQUIRES a defined entry and exit.
- Building = **grid of cells, tap/drag to add/remove walls** (walls are real LEGO-style bricks, colour selectable).
- Camera while driving: **kid can toggle** between tilted top-down follow and behind-the-car chase.
- Game elements: **timer + 1–3 stars** with best record, **collectible coins**, **random maze generator** (Easy/Medium/Hard), **hint** (arrow showing the way).

## Global Constraints (maze)

- Cell = 8 studs (reuse `CELL` from src/core/city.ts). Wall cells render as brick walls 2 bricks tall (6 plates) filling the cell; path cells are floor (baseplate). Corridors are one cell wide, which fits every drivable template (≤ 6 studs wide incl. wheels).
- Maze sizes: odd numbers of cells per side, 7 ≤ n ≤ 21 (Easy 7×7, Medium 11×11, Hard 15×15 defaults).
- Entry and exit: path cells on the OUTER border, not the same cell, not corners. A maze is "playable" only if a path exists entry→exit (4-neighbour BFS over path cells). The Drive button is disabled with a visible hint until playable.
- Coins: only on path cells, not on entry/exit.
- Save: `SaveData.mazes: Maze[]`, `SaveData.mazeRecords: Record<string, { timeMs: number; stars: 1|2|3; coins: number }>` keyed by maze id (`tpl:<id>` for templates). Schema bump (coordinate with the figures branch: one bump to 3 covering both, with migration adding `mazes: []`, `mazeRecords: {}`).

## Types (src/core/maze.ts)

```ts
export interface Cell { cx: number; cz: number }
export interface Maze {
  id: string
  name: string
  w: number // cells along X (odd)
  h: number // cells along Z (odd)
  walls: string[] // "cx,cz" keys of wall cells
  entry: Cell | null
  exit: Cell | null
  coins: string[] // "cx,cz" keys
  wallColor: number // colour id
  floorColor?: number // baseplate colour id (default 24 light bluish gray)
  createdAt: number
  updatedAt: number
  templateId?: string
}
export interface MazeTemplate { id: string; name: LocalizedText; difficulty: 1|2|3; maze: Omit<Maze,'id'|'createdAt'|'updatedAt'> }
```

### Task M1: Maze core + templates (pure TS)

**Files:** `src/core/maze.ts` (+ `maze.test.ts`), `src/core/mazeGen.ts` (+ test), `src/content/mazes/{index,easy,medium,hard,spiral,heart}.ts` (+ `mazes.test.ts`).

- `cellKey`, `createEmptyMaze(w, h, opts)` (outer ring all walls), `toggleWall(maze, cell, wall: boolean)` (no-op on entry/exit cells; removing a coin when walling its cell), `paintWalls(maze, cells, wall)` for drag strokes, `setEntry/setExit(maze, cell)` → `{maze} | {error: 'not_border'|'corner'|'is_wall'|'same_cell'}` (setting entry/exit on a border wall cell carves it open — kids tap the border to make a door; define this clearly and test it), `toggleCoin`, `isBorder`, `isCorner`, `neighbors4`.
- `solve(maze, from?: Cell): Cell[] | null` — BFS shortest path from `from ?? entry` to exit over path cells; `isPlayable(maze)`; `playabilityError(maze): 'no_entry'|'no_exit'|'no_path'|null`.
- `nextHintCells(maze, from: Cell, count = 4): Cell[]` — next cells along the shortest path from the car's cell (for hint arrows).
- `starThresholds(maze)`: based on shortest path length L (cells): 3⭐ ≤ L×1.6 s, 2⭐ ≤ L×2.6 s, else 1⭐ (seconds; tune constants as named exports); `rateRun(maze, timeMs) → 1|2|3`.
- `mazeGen.ts`: `generateMaze(difficulty: 1|2|3, seed: number, opts?) → Maze` — perfect maze via iterative recursive backtracker on the odd grid (seeded PRNG, e.g. mulberry32), entry on the west border, exit on the east border (random rows), Medium/Hard add a few loops (remove k random walls) and Hard is larger; place coins on dead ends (Easy 3, Medium 5, Hard 8). Deterministic for a seed (test).
- Templates: `easy` (7×7), `medium` (11×11), `hard` (15×15) — hand-authored or generated-and-frozen literal data; `spiral` (11×11 spiral corridor to the centre and back out), `heart` (15×15 maze inside a heart-shaped outline — walls outside the heart). Each has entry, exit, coins, a wall colour, vi/en names; `MAZE_TEMPLATES`, `getMazeTemplate(id)`. Test: every template is playable, entry/exit valid, coins on path cells, sizes odd and in range.
- Must not import React/DOM/three.
