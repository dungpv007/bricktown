# BrickTown — Sharing Creations (Plan)

Builds on Phase 1, the figures/colours batch and Maze mode. Phase 1 Global Constraints still bind.

## User decisions (2026-10-01)

- Channels: **link + QR code** (creation encoded inside the link — no server) and **file** (`.bricktown`).
- Shareable: **own models** (blueprints), **with build instructions** (receiver can build it step by step in Guided mode), **mazes** (with the sender's best time as a challenge), **whole city** (roads + placements + the blueprints it uses).
- No online gallery / accounts (the game stays local-only).

## Key constraints

- No backend. A link is `<SHARE_BASE_URL>/#s=<payload>`; `SHARE_BASE_URL` = `import.meta.env.VITE_SHARE_BASE_URL ?? location.origin`. Links only open on other devices once the game is hosted at a public URL (documented in the share dialog: if the origin is localhost/LAN, show a small hint that the file option works everywhere).
- Payload: `base64url(deflate-raw(json))` using **fflate** (small, sync, works in Node tests and old Safari). Compact JSON: part-id table + bricks as tuples `[partIdx, x, y, z, r, c, figIdx?]`, fig styles table, short keys.
- QR: generated offline with a small QR library (e.g. `qrcode-generator`), error level L/M; if the link is too long for a QR (> ~2,300 chars), hide the QR and suggest the link or file.
- Safety (kids' app): imports are untrusted. Strict validation: known `app`/`v`/`kind`, decompressed size cap (2 MB, guard against zip bombs), counts limits (≤ 1500 bricks per model, ≤ 60 blueprints per city, city size ≤ 48, maze w/h odd 7–21), every part id/colour/fig value validated (unknown → friendly rejection, never crash), names sanitised (trim, strip control chars, ≤ 40 chars), no HTML rendering of names (React text only). All ids are re-generated on import (no collisions with existing data); references remapped.
- Import is always confirmed by the user via a preview (3D thumbnail, name, kind icon, brick count) — never auto-applied. Opening a share link clears the hash after handling.
- Save schema: add `sharedTemplates: Template[]` (imported "with instructions" models appear in Guided picker under a "Được chia sẻ" section) and `mazeChallenges: Record<mazeId, {timeMs, from?: string}>`; bump schema with a migration filling defaults.

## Share format (src/core/share.ts)

```ts
type ShareKind = 'model' | 'maze' | 'city'
interface SharePackage {
  app: 'bricktown'; v: 1; kind: ShareKind; name: string; createdAt: number
  model?: { blueprint: Blueprint; steps?: number[][] }           // steps present = "with instructions"
  maze?: { maze: Maze; best?: { timeMs: number; stars: 1|2|3 } }
  city?: { city: CityState; blueprints: Blueprint[] }            // tpl:<id> sources stay references
}
```

### Task S1: Share core (pure TS)

**Files:** `src/core/share.ts` (+ test), `src/core/shareCodec.ts` (+ test; compact encoding + fflate), `src/core/shareImport.ts` (+ test; validate, sanitise, remap ids, apply to SaveData).

- `buildModelPackage(bp, { withSteps })` (steps = `autoSteps` validated with `validateTemplate`; if invalid, fall back to a safe ordering by y), `buildMazePackage(maze, record?)`, `buildCityPackage(city, blueprints)` (only blueprints referenced by placements).
- `encodeShare(pkg) → string` (base64url), `decodeShare(str) → SharePackage | { error: 'corrupt'|'too_big'|'unsupported'|'invalid' }`; `shareLink(pkg, base)`, `parseShareHash(hash)`; file text = same base64url payload wrapped as `{"bricktown":"<payload>"}` (`.bricktown`).
- `planImport(data, pkg) → ImportPlan` (what will be added/replaced, counts) and `applyImport(data, plan) → SaveData`: model → new blueprint (+ `sharedTemplates` entry when steps); maze → new maze (+ challenge time); city → replaces current city after confirm, imported blueprints added with new ids and placements remapped.
- Tests: round trips for all kinds (incl. figures, trans/metal colours, printed tiles), link length for a 200-brick house, malicious inputs (garbage, huge decompressed size, unknown parts, negative coords, absurd counts, HTML/script in names), id remapping, schema migration.

### Task S2: Share & import UI

- Share buttons (🔗 icon, data-testid `share-<kind>`): Blueprint library item, maze picker item, city screen.
- Share dialog: options toggle "kèm hướng dẫn lắp" (models) → shows QR code (if fits), **Chia sẻ** (Web Share API: `navigator.share({ title, url })`, and `files` with the `.bricktown` file where supported), **Sao chép link**, **Tải file**. Icons first, short labels, ≥64px.
- Import entry points: (1) app opened with `#s=` → after boot, preview dialog; (2) "📥 Nhập" button in the main menu / library → file picker (`.bricktown`, `.json`) and paste-a-link field; (3) drag-and-drop a file onto the window (desktop).
- Preview dialog: 3D thumbnail, name, kind icon, counts; ✓ adds (or ✓ "Thay thành phố" with a second confirm for city), ✗ cancels; friendly error card for invalid/too-big/unsupported.
- Guided picker: "Được chia sẻ" section listing `sharedTemplates` (build step by step like built-in templates).
- Maze: imported maze shows the sender's time as a challenge badge ("Vượt 42s?").
- i18n vi + en; e2e: share a blueprint → decode link in a second page → import → appears in library; with instructions → appears in Guided shared section and can be completed; maze share/import with challenge; city share/import replace flow; invalid link shows error card.
